# 评测 Skill 生成体系设计

> 本文档描述「用评测 skill 评测 skill」的设计:通过一个 meta-skill 把「评测 skill 模板(挖空版)」+「待评测 skill」转化为「评测 skill」,再用它对 agent 的产出打分。评测 skill 支持**多指标加权打分**。

## 1. 背景与诉求

评测平台需要评测 skill。诉求如下:

- 构建一个**评测 skill 生成 skill**(meta-skill)。
- 输入:评测 skill 模板(挖空版)+ 待评测 skill。
- 输出:评测 skill(填充后的完整版)。
- 评测 skill 使用时,输入为 `input`(agent 的输入)、`output`(agent 的输出)、`groundtruth/约束`(用来打分的参考答案或约束条件),输出为**打分**(各指标分数 + 加权总分)。

## 2. 整体架构:两层 skill

```
┌──────────────────────────────────────────────────┐
│  第一层:评测 skill 生成 skill(meta-skill)        │
│  输入 : 评测 skill 模板(挖空版) + 待评测 skill     │
│  输出 : 评测 skill(填充后的完整版)                │
└──────────────────────────────────────────────────┘
                        │ 产出
                        ▼
┌──────────────────────────────────────────────────┐
│  第二层:评测 skill(打分器)                        │
│  输入 : input + output + groundtruth/约束         │
│  输出 : 各指标分数 + 加权总分(0~1)                │
└──────────────────────────────────────────────────┘
```

- **meta-skill 跑一次**,为每个待评测 skill 生成一个专属评测 skill。
- **评测 skill 反复使用**,对大量 `(input, output, groundtruth)` 样本逐条打分。

## 3. 评测 skill 模板(挖空版)

模板是一个 markdown 骨架,含**五个待填区块**(多指标)+ 一个固定流程。挖空部分用 `{...}` 占位,由 meta-skill 填充。

```markdown
# 评测 Skill:{skill_name}

## 评测指标
{metric_definitions}
<!-- 挖空:定义多个评测指标,例如:
  1. 正确性 —— 输出与 groundtruth 是否一致
  2. 完整性 —— 是否覆盖所有要求
  3. 格式规范 —— 是否符合输出格式要求 -->

## 指标含义
{metric_meanings}
<!-- 挖空:每个指标的具体含义 -->

## 评测标准
{scoring_criteria}
<!-- 挖空:每个指标的打分标准(rubric) -->

## 指标权重
{metric_weights}
<!-- 挖空:各指标的权重,和为 1 -->

## 案例
{examples}
<!-- 挖空:正例/反例,覆盖各指标的判定口径 -->

## 评测流程
1. 读取 input、output、groundtruth/约束。
2. 对每个指标按「评测标准」分别打分。
3. 按「指标权重」加权合成总分。
4. 输出各指标分数 + 加权总分(0~1,可选附带理由)。
```

### 挖空区说明

| 区块 | 含义 | 由谁填充 |
|------|------|---------|
| `metric_definitions` | 定义多个评测指标 | meta-skill |
| `metric_meanings` | 每个指标的具体含义 | meta-skill |
| `scoring_criteria` | 每个指标的打分标准 / rubric | meta-skill |
| `metric_weights` | 各指标的权重(和为 1) | meta-skill |
| `examples` | 正例与反例 | meta-skill |

固定不变的是「评测流程」,保证所有评测 skill 的输出契约一致。

## 4. 评测 skill 生成 skill(meta-skill)

### 输入

| 字段 | 类型 | 说明 |
|------|------|------|
| `template` | 文本 | 评测 skill 模板(挖空版) |
| `target_skill` | 文本 | 待评测 skill 的完整内容 |

### 输出

| 字段 | 类型 | 说明 |
|------|------|------|
| `eval_skill` | 文本 | 填充好五个挖空区后的完整评测 skill |

### 职责

1. 理解 `target_skill` 的目标、输入输出、成功标准。
2. 据此填充模板的五个挖空区:定义多个指标、说明含义、给出标准、设定权重、补齐案例。
3. 产出可独立使用的评测 skill。

## 5. 评测 skill 使用(打分流程)

### 输入

| 字段 | 类型 | 说明 |
|------|------|------|
| `input` | 文本 | agent 的输入 |
| `output` | 文本 | agent 的输出 |
| `groundtruth` / `constraints` | 文本 | 参考答案或约束条件,用于打分 |

### 输出

| 字段 | 类型 | 说明 |
|------|------|------|
| `metrics` | dict | 各指标分数,如 `{"正确性": 0.9, "完整性": 0.7}` |
| `total_score` | float | 按权重加权后的总分,0~1 |
| `reason` | 文本(可选) | 打分理由 |

## 6. 端到端示例

**待评测 skill**:一个「代码生成」skill(根据需求生成 Python 函数)。

**Step 1 — meta-skill 填充模板,产出评测 skill**:

```markdown
# 评测 Skill:code-gen

## 评测指标
1. 正确性   —— 代码能否通过测试用例
2. 完整性   —— 是否覆盖需求的所有要求
3. 代码规范 —— 命名、结构是否规范

## 指标含义
- 正确性:在容器中运行 output,与 groundtruth 的测试用例对比。
- 完整性:是否实现需求中的所有功能点。
- 代码规范:变量命名、函数拆分是否符合常规规范。

## 评测标准
- 正确性:全部测试通过 → 1.0;部分通过 → 通过数/总数;全失败 → 0.0
- 完整性:全部功能点覆盖 → 1.0;缺一个 → 0.5;缺多个 → 0.0
- 代码规范:规范 → 1.0;基本规范 → 0.5;混乱 → 0.0

## 指标权重
- 正确性:0.6
- 完整性:0.3
- 代码规范:0.1

## 案例
正例:input="写一个 add(a,b) 返回和",output="def add(a,b): return a+b",
      groundtruth='[{"input":"1,2","output":"3"}]'
      → 正确性 1.0,完整性 1.0,代码规范 1.0 → 总分 1.0
反例:input="写一个 add 和 sub",output="def add(a,b): return a+b",
      groundtruth='[{"add":"1,2->3","sub":"5,3->2"}]'
      → 正确性 1.0,完整性 0.5(缺 sub),代码规范 1.0 → 总分 0.85

## 评测流程
1. 读取 input、output、groundtruth/约束。
2. 对每个指标按「评测标准」分别打分。
3. 按「指标权重」加权合成总分。
4. 输出各指标分数 + 加权总分(0~1,可选附带理由)。
```

**Step 2 — 评测 skill 使用**:

```
input       = "写一个函数,输入两个数返回它们的和"
output      = "def add(a, b):\n    return a + b"
groundtruth = '[{"input":"1,2","output":"3"}]'

→ 评测 skill 输出:
  metrics     = {"正确性": 1.0, "完整性": 1.0, "代码规范": 1.0}
  total_score = 1.0 × 0.6 + 1.0 × 0.3 + 1.0 × 0.1 = 1.0
  reason      = "测试通过,功能完整,命名规范"
```

## 7. 与 EvoSkill scorer 的关系

评测 skill 本质是把 EvoSkill 的 scorer 概念 `(question, predicted, ground_truth) -> score` 扩展为:

1. **自包含**:评测逻辑 + 多指标 + 权重 + 案例打包成一个 skill 文件,而非散落的函数。
2. **动态生成**:不再手写每个 scorer,而是由 meta-skill 按模板批量生成。
3. **可复用**:评测 skill 是独立产物,可跨平台、跨任务复用。
4. **多维度**:从单分数扩展为多指标加权,评测更细粒度。

## 8. 待确认 / 可扩展项

- **打分粒度**:当前设计为各指标 0~1 连续分;若某指标只需二值,`scoring_criteria` 可定义为 0/1。
- **理由是否必填**:当前 `reason` 为可选;若后续要做自动优化,可设为必填,作为改进依据。
- **权重是否固定**:当前权重由 meta-skill 在生成时确定;若需用户干预,可把权重开放为评测 skill 的输入参数。
- **meta-skill 的迭代**:meta-skill 本身是否也参与进化(用评测结果反哺生成策略),可作为后续方向。
